# 04 · 固件架构说明

> 对应源码：`USER/inc/`（13 个头文件）＋ `USER/src/`（11 个 .c）＋ `MDK/`（Keil MDK5 工程）。
> 阅读顺序建议：`app_config.h` → `bsp_pin.h` → `main.c` → 各 `bsp_*.c`。

---

## §1 分层结构（为什么不是一个大文件）

```text
main.c / interrupts_cw32l010.c     应用逻辑层：状态、按键语义、界面内容
        ▲
bsp_*.c（11 个模块）              板级支持层：一类硬件 = 一个模块
        ▲
CW32L010_Lib/                     芯片标准库（老师/官方提供，不修改）
```

| 模块 | 职责 | 教学要点 |
|---|---|---|
| `bsp_pin.h` | **全工程唯一的引脚映射表** | 「引脚改了只改一处」的可维护性 |
| `app_config.h` | 产品型号开关（外挂款/内置款） | 一套代码覆盖两种产品 |
| `bsp_button.c` | 多键扫描与去抖 | 上拉输入、15ms 稳定判据 |
| `bsp_pwm.c` | ATIM 双通道 PWM 初始化与占空比设置 | 频率/分辨率计算 |
| `bsp_detect.c` | 磁吸吸附检测（含去抖） | 复用引脚、状态去抖 |
| `bsp_power.c` | 停机（STOP）与唤醒 | 低功耗与外设恢复 |
| `bsp_adc.c` | 电池电压采样（均值） | 采样时间、分压换算 |
| `bsp_i2c.c` / `bsp_oled.c` / `bsp_oled_text.c` | 软件 IIC + OLED 显示原语 | 时序模拟、字符串描画分离 |
| `bsp_timer.c` | 1ms 时基 | 软件定时任务节拍 |
| `interrupts_cw32l010.c` | 中断与周期调度入口 | 中断里做什么、不做什么 |

> **设计哲学**：`main.c` 只表达「产品行为」（开关机、亮度、分组、界面），
> 不知道任何寄存器细节；换 MCU 时，原则上只重写 `bsp_*`，`main.c` 的语义不变。

## §2 按键与功能定义

| 按键 | 外挂款（5 键） | 内置款（7 键） |
|---|---|---|
| BTN1 | **整机开关**（LDO CE + 停机/唤醒） | 整机开关 |
| BTN2 / BTN3 | 当前组亮度 **−10% / +10%** | 同左 |
| BTN4 | **分组切换**（组1 ⇄ 组2） | 分组切换 |
| BTN5 | **全部亮灭** | 组1 亮灭 |
| BTN6 | — | 组2 亮灭 |
| BTN7 | — | 全部亮灭 |
| 引脚（外挂） | PA02 PA04 PA05 PA06 PB03 | — |
| 引脚（内置） | — | PA00 PA01 PA02 PA04 PA05 PA06 PB03 |

`BTN_PORT[]/BTN_PIN[]` 两个常量数组把「按键序号 → 引脚」的映射集中管理，
新增/删除按键只改数组与宏，扫描代码不用动。

## §3 PWM 调光：2400 级是怎么来的

```c
/* bsp_pwm.h */
#define PWM_PRESCALER   0          /* 不分频：计数时钟 = 48MHz */
#define PWM_FREQ_HZ     20000      /* 20kHz（驱动芯片规格下限，无可见频闪） */
#define PWM_ARR         (PWM_CLK_HZ / (PWM_PRESCALER + 1) / PWM_FREQ_HZ - 1)
/*  = 48,000,000 / 20,000 - 1 = 2399  → 2400 级（占空比步进 1/2400 ≈ 0.042%） */
```

- **通道映射**：PWM1 = PB01 = `ATIM_CH2`（LED 组1）；PWM2 = PA03 = `ATIM_CH3`（LED 组2）；
- **亮度表示**：以**千分数**（0–1000）保存，默认 500（50%），按 10%（100）步进调整；
- **占空比计算**：`cmp = 亮度千分数 × (ARR+1) / 1000`；
- **输出刷新**：每次状态变化后再统一写寄存器（`ApplyOutputs()`），避免中间态闪烁。

```c
/* main.c 的核心输出公式（外挂款） */
d1 = (g_power_on && g_grp1.on && g_det1) ? g_grp1.brightness : 0;
d2 = (g_power_on && g_grp2.on && g_det2) ? g_grp2.brightness : 0;
```

> 学习点：**产品逻辑被压缩成一个布尔表达式** —— 「电源 × 点亮 × 亮度 × 已吸附」。
> 任何一路条件不满足，输出即为 0。这种写法比层层 `if` 更容易检查与验证。

## §4 磁吸检测：去抖与联动

```c
/* bsp_detect.c 思路 */
5ms 周期采样 → 与上次原始值比较 → 连续 DETECT_HOLD_CNT 次一致 → 才认定状态翻转
```

- 为什么不能「读一次就用」：磁吸接触瞬间会抖动（弹跳），单次采样极易误判；
- 为什么放在 5ms 节拍：与按键扫描同节拍，一次遍历完成两类去抖，主循环零负担；
- **联动**：一旦检测状态变化 → 立即 `ApplyOutputs()`（**脱落即灭**）→ 置「界面刷新请求」；
- 内置款下整个模块编译为空（`#if BSP_DETECT_ENABLED`），且 `g_det` 恒为 1，复用同一套输出公式。

> ⚠️ 常见错误：把检测写成轮询读引脚 → 灯会「一闪一闪」。正确做法是**去抖 + 只在状态翻转时动作**。

## §5 整机开关与低功耗

```text
关机：BTN1 长按/按下 → g_sleep_req=1 → 关闭输出 → LDO_CE_Disable() → 进 STOP（__WFI）
唤醒：任意键 GPIO 中断 → 退出 STOP → 重新使能 HSI → 恢复外设 → LDO_CE_Enable()
```

三个容易被忽略的细节（都在源码注释里）：

1. **HSI 在 STOP 后需要重新使能**：停机时内部高速时钟关闭，外设寄存器保留但时钟没了；
2. **唤醒后 300ms 吞键保护**：防止「按下开机键 → 唤醒瞬间又被当成关机操作」；
3. **同步关闭两路输出再断电**：`ApplyOutputs()` 先把占空比清 0，再拉低 CE，避免断电瞬间的异常驱动。

> 测量建议：关机静态电流应以 µA 级为目标（不同 LDO 与外围会有差异），
> 若发现偏高，优先排查：LDO 静态电流、分压电阻通路、LED 驱动使能脚是否真的关断。

## §6 ADC 电量采样

```c
/* bsp_adc.c */
ADCCLK = PCLK / 8 = 6MHz;         /* 规格内（≤48MHz），兼顾采样精度与速度 */
模式   = 单次转换；通道 = ADC_IN7（PB00）；采样时间 = 42 周期；
VBAT   = 多次采样平均值 × VREF / 4095 × 分压比;
```

- **多次均值**（`VBAT_AVG_NUM`）：抑制电源纹波与 PWM 干扰带来的抖动；
- **分压比**：电池电压高于 VREF，必须经电阻分压后进 ADC，代码里用 `VBAT_DIV_RATIO` 还原；
- 采样节奏：50ms 一次（比界面刷新快，比按键慢，够用且省电）。

> 调试技巧：用「已知电压源 + 万用表」双表法校准分压比，比盲调系数快得多。

## §7 OLED 界面

| 显示项 | 内容 | 刷新节奏 |
|---|---|---|
| 电池电压 | mV（如 `3850 mV`） | 50ms 采样，200ms 请求刷新 |
| 电量百分比 | 千分数换算成 % | 同左 |
| 组1 / 组2 | 亮灭 + 亮度档位（如 `G1 ON 500`） | 状态变化即时刷新 |
| 吸附状态 | 每组 DET 是否吸附 | 翻转时刷新 |

- 采用**软件 IIC**（PB05/PB06）：无需硬件 IIC 外设，引脚可自由选择；
- **刷屏只在主循环做**：全屏刷新耗时数毫秒，放进中断会破坏 1ms 时基——这是分层的现实理由；
- 显示原语（`bsp_oled.c`）与内容（`main.c`）分离：换屏只需改原语。

## §8 双型号配置（一行宏切换）

```c
/* USER/inc/app_config.h */
#define PRODUCT_VARIANT_EXTERNAL   0    /* 外挂款：磁吸 4pin + 吸附检测（5 键） */
#define PRODUCT_VARIANT_BUILTIN    1    /* 内置款：LED 焊在板上，无需检测（7 键） */

#define APP_PRODUCT_VARIANT        PRODUCT_VARIANT_EXTERNAL   /* ← 烧录前改这里 */
```

切换后自动联动：

| 项 | 外挂款 | 内置款 |
|---|---|---|
| `BSP_DETECT_ENABLED` | 1（占用 PA00/PA01） | 0（PA00/PA01 作按键） |
| 按键数 `BTN_MAX_NUM` | 5 | 7 |
| 输出条件 | 需「已吸附」 | 仅需电源 + 点亮 |

> 这是一种非常有价值的工程习惯：**把「产品差异」收敛到一个宏**，
> 代码路径共用、测试共用，只有配置不同。

## §9 移植与扩展建议

| 想做的事 | 建议起点 |
|---|---|
| 换 MCU（如移植到 STM32/其他国产 M0+） | 保留 `main.c` 语义，重写 `bsp_*.c`；先移植 PWM 与按键 |
| 加蓝牙/串口上报（对接工位数据） | 在 `main.c` 的 200ms 刷新节点挂一个上报任务；OPC UA 类协议需网关侧支持 |
| 做自动调光（感知环境光） | 新增 `bsp_light.c`（光敏 ADC）+ 在 `ApplyOutputs()` 前插入亮度策略；保留手动覆盖 |
| 增加第三路灯组 | `PWM_CH3` + 一组 BSP_DETECT + 按键宏扩展（注意引脚余量） |
| 做低功耗唤醒后保持状态 | 现方案复位后回默认态；可把状态存 Flash/RAM 保留区（进阶练习） |

## §10 代码风格约定（本包要求）

1. **一个模块一类硬件**：新增硬件 = 新增 `bsp_xxx.c/h`，不在 `main.c` 里直接操作寄存器；
2. **引脚只在 `bsp_pin.h` 定义**，其他文件不得出现裸引脚号；
3. **中断里只做短任务**（采样、去抖、置标志），耗时操作交主循环；
4. **产品开关/型号差异用宏**，不用运行时分支，降低复杂度；
5. **注释解释“为什么”**，而不是复述代码（本包所有 `bsp_*.c` 头部均按此写）。
