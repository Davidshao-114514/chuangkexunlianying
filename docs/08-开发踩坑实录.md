# 08 · 开发踩坑实录（真实迭代过程）

> 这一篇是本学习包**最有价值的部分**：它记录的不是「设计好的结果」，而是
> **「真实踩过的坑 → 根因 → 解决」**。全部来自本项目的实际开发过程。
>
> 工程师的能力，大部分是在这些坑里长出来的。我们把它们完整留在这里。

---

## 阶段 1：框架搭建

- 基于 CW32 官方例程（`gpio_blink` 结构）搭 UserApp 骨架；
- 从另一块 H563 工程**移植 OLED / I2C 驱动**；
- 确定 **HSI 48MHz 单时钟方案**（无外部晶振），ATIM 输出 PWM。

> 💡 学习点：移植驱动比重写更快，但要先弄清「两边的时钟与外设假设是否一致」。

---

## 阶段 2：需求快速迭代

- **按键映射反复调整**：7 键 → 5 键 → 最终 **3 键**（PB03 开关机 / PA04 亮度− / PA05 亮度+），
  用「单击 / 长按 / 双击」把功能压缩进 3 个按键；
- 加入**磁吸吸附检测**与「外挂款 / 内置款」双型号开关；
- 建立**电池过放保护状态机**，阈值两次调整（3.5/3.2V → **3.35/3.2V**，提高电池利用率）。

> 💡 学习点：**按键越少，交互设计越重要**。功能不是靠键多，而是靠状态机区分操作语义。

---

## 阶段 3：硬件联调攻坚（耗时最长的阶段）

### 3.1 OLED 点亮马拉松（4 轮方案）

| 轮次 | 尝试 | 结果 |
|---|---|---|
| 1 | 直接套用 SSD1306 初始化序列 | 不亮（CH1115 不认 0x8D 电荷泵命令） |
| 2 | 网络教程的 CH1115 序列 | 仍不亮（方向/偏移/电荷泵参数不符） |
| 3 | GitHub 上的开源库 | 有显示但方向与偏移错误 |
| 4 | **商家官方 C51 源码** | ✅ 定位成功 |

**根因**：多处参数差异同时存在 —— 方向（`A0/C0`）、显示偏移（`D3=0x38`）、
电荷泵（`0xAD 0x8B 0x33`）、IREF（`0x82` 配置）。

> 💡 学习点：遇到「同型号屏不同批次/不同厂」时，**以厂家官方例程为准**，不要迷信网上的通用序列。

### 3.2 ADC 测不准（三阶段）

| 阶段 | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | 电池读数恒定在满量程一半 | **VBAT 直供 MCU** → 分压与 ADC 参考同源，比例恒定 | 改用**内部 BGR 1.2V 反推 VDD** |
| 2 | LED 点亮后读数乱跳 | 双通道非同时采样，撞上 PWM 造成的电源波动 | **成对交替采样 + IIR 平滑** |
| 3 | 静态功耗偏高（~210µA） | 外部 10K/10K 分压**常通耗电** | **拆除外部电路**，改纯 BGR 反推，且 BGR 仅在测量时开启 |

> 💡 学习点：**"比例测量失效"是直供电池方案经典陷阱**—— ADC 参考跟电源同源时，
> 测出来的永远是"固定比例"。要测电源电压，必须有一个**绝对参考**（BGR/LDO 参考）。
> 同时：分压电阻是「静态耗电大户」，电池设备能省则省。

### 3.3 频闪 / 啸叫 / 功耗：PWM 频率调优史

`20kHz → 30kHz → 5kHz → 1kHz → 8kHz（定稿）`

**根因**：驱动芯片 RY3730 手册规定调光频率 **100Hz ~ 10kHz** ——
超出范围或过低都会出问题；最终以 **8kHz + 亮度下限 3%** 收尾（低占空比频闪治理）。

> 💡 学习点：**PWM 频率不是越高越好**，要读驱动芯片手册的推荐区间；
> 低亮度频闪往往不是频率单一问题，需配合**最小占空比下限**一起解决。

### 3.4 休眠唤醒反复踩坑（四个连环坑）

| 现象 | 根因 | 解决 |
|---|---|---|
| **唤不醒** | 唤醒边沿方向错（本板按键**高有效**，需上升沿） | 配置上升沿唤醒 |
| **唤醒即重启** | 唤醒恢复时序不当（3V3 未稳时按键扫描误判） | **延迟初始化 + 吞咽窗口** |
| **松手即重启** | 机械按键**释放回弹**产生瞬态边沿，被当成新的唤醒 | 等释放 + 100ms 消抖窗 + 清标志再睡 |
| **关机后开不了机** | PB03 供电随 CE 断开而消失 | 硬件改版：PB3 由 VBAT 分压常电 |

> 💡 学习点：低功耗调试的坑几乎都在**"边沿语义"和"时序"**上——
> 机械按键的回弹、电源建立所需的时间，必须显式处理（消抖窗、清标志、延迟初始化）。

### 3.5 按键误触

- 现象：安静环境正常，**PWM 一开就零星误触**；
- 根因：按键节点为**高阻**，耦合了 PWM 噪声；
- 解决：**硬件把下拉电阻改小**（降低节点阻抗）。

> 💡 学习点：软件消抖解决不了「电气层面的噪声耦合」——**该改硬件就改硬件**。

## 阶段 4：体验优化

- **无级调光**：长按连续调节，**三段加速**（60ms/步 → 1.1s 后 30ms/步 → 1.9s 后 12ms/步），步进 0.5%；
- **复合操作**：单击 = 一步微调；长按 ≥300ms = 连续调节；双击（≤350ms）= 切换功能
  （双击−切换调节对象 A→B→一起；双击+切换点亮模式）；
- **Flash 亮度记忆**：亮度变更 2s 后自动保存（两组独立）+ 关机时保存；
  开机时若 RTC 差值 ≤1 小时则恢复，否则默认 10%（**跨 Reset 有效，掉电自然过期**）；
- **屏幕迭代**：0.91"(128×32) → 0.96"(128×64) → 最终 **0.5" CH1115 88×48**，UI 全部重排为 6 行 × 14 字符；
- **代码瘦身**：删除所有调试显示（raw/i12/ST-EV/开机动画）。

> 💡 学习点：**体验优化阶段才是产品成型的地方**——同样的硬件，
> 交互细节（加速曲线、双击语义、记忆策略）决定用户觉得"好用"还是"凑合"。

## 关键踩坑速查表（可直接当排错清单用）

| 现象 | 根因 | 解决 |
|---|---|---|
| 屏幕全黑 | CH1115 不认 SSD1306 的 DC-DC 命令（0x8D）、方向/偏移错误 | 商家官方序列：`0x82` IREF + `0xAD 0x8B 0x33` + `A0/C0` + `D3 0x38` |
| 电池读数恒为 3.3V | VBAT 直供 → 分压/参考同源，比例恒定 | 内部 **BGR 反推 VDD** |
| LED 亮起后电压乱跳 | 双通道非同时采样遇 PWM 波动 | **成对交替采样 + 平滑** |
| 低亮度频闪 | 调光频率脱离 RY3730 推荐区（100Hz–10kHz） | **8kHz + 3% 下限** |
| 关机松手即重启 | 按键释放回弹瞬态被当唤醒沿 | **等释放 + 消抖窗 + 清标志** |
| 按键误触 | 高阻节点耦合 PWM 噪声 | **硬件下拉电阻改小** |
| 唤醒后花屏 | 屏幕掉电重启需完整初始化 | **唤醒延时 500×1ms 后 OLED_Init** |

## 从这些坑里，我们提炼出 6 条工程原则

1. **以厂家官方例程为准**（尤其外设初始化序列），网络教程只能参考；
2. **测电源要有绝对参考**（BGR/基准源），否则比例测量必然失效；
3. **频率与占空比要一起设计**（驱动手册 + 最小占空比下限）；
4. **低功耗的关键是时序**：唤醒沿、消抖窗、初始化延迟，一个都不能少；
5. **软件治不了的噪声，回硬件解决**（下拉电阻、地线、去耦）；
6. **把踩坑写下来**：同一个坑第二次踩，成本才是真正的浪费——这也是本学习包存在的原因。
